# B4 · Presets

3 lessons · 14 min · the idea here is that **you save render settings once and point at them**.

## 1. Nine kinds, one per level <span class="tks-min">5 min</span> { #1-nine-kinds-one-per-level }
<div class="tks-video" data-video="B4.1">Render Presets explained: nine kinds, set once per tier</div>

Dial your settings in, save a preset, assign it on any level. Each kind cascades on its own, so a scene Render preset and a layer Colour preset can both win.

Read more: [Render Presets](../features/render_presets.md) · [Use Render Presets](../workflows/use_render_presets.md)

## 2. When a preset goes dirty <span class="tks-min">5 min</span> { #2-when-a-preset-goes-dirty }
<div class="tks-video" data-video="B4.2">Changed a setting after applying a preset? Dirty state, Accept and Revert</div>

Change a setting and the preset no longer matches. Accept saves your change into it, Revert puts the stored value back. Per value, per kind, or all at once.

Read more: [Dirty State](../features/render_presets.md#dirty-state)

## 3. Where presets live <span class="tks-min">4 min</span> { #3-where-presets-live }
<div class="tks-video" data-video="B4.3">Where presets are stored: Add-on, Project, Shared, Local</div>

Four folders. Project travels with the .blend, Shared is the team standard and stays locked so nobody overwrites it.

Read more: [Storage Tiers](../features/render_presets.md#storage-tiers)
