# C2 · Batch Render

5 lessons · 23 min · the idea here is that **one click renders everything**.

## 1. The toggle decides, not the selection<span class="tks-min">4 min</span>

<div class="tks-video" data-video="C2.1">Why did my layer not render? The render toggle, not the selection</div>

The batch is built from each layer's render toggle. Which row is highlighted drives editing, not rendering. Tree order is render order.

Read more: [Batch Render](../features/batch_render.md#what-gets-rendered)

## 2. In front of you, or in the background<span class="tks-min">5 min</span>

<div class="tks-video" data-video="C2.2">Batch render in Blender or in the background - keep working while it renders</div>

Foreground locks Blender and shows the render. Background saves the file once and works through the queue while you keep going.

Read more: [Batch Render Your Takes](../workflows/batch_rendering.md)

## 3. Choosing what to render<span class="tks-min">4 min</span>

<div class="tks-video" data-video="C2.3">Render this scene, all scenes, by tag, resume, or retry failed</div>

The render menu is a list of scopes. Resume skips what is done, Retry picks up only what failed.

Read more: [The Render Menu](../features/batch_render.md#the-render-menu)

## 4. Reading the queue<span class="tks-min">4 min</span>

<div class="tks-video" data-video="C2.4">Reading the render queue and getting a real time estimate</div>

Every layer carries a status. Estimates correct themselves as the run goes, and Calibrate learns the times before you start.

Read more: [Render Queue](../features/batch_render.md#render-queue)

## 5. Never overwriting a render again<span class="tks-min">6 min</span>

<div class="tks-video" data-video="C2.5">Render versioning: v001, sub-versions, lock as final, archive old renders</div>

Versions and sub-versions feed your tokens. Detect from Disk continues past what is already there, and Lock as Final protects one.

Read more: [Versions](../features/batch_render.md#versions-sub-versions-notes)
