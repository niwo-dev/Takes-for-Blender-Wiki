## 2. Variants explained: Product, Part, Pool, State <span class="tks-min">5 <span class="tks-min__u">min</span></span> { #2-variants-explained-product-part-pool-state }
<div class="tks-video" data-video="B2.2">Variant Switch explained: Product, Part, Pool, State</div>

A Product is the whole thing. Parts are its pieces, each with a pool of materials. A State is one named look that picks a material for every Part at once.

Read more: [Variant Switch](../features/variant_switch.md) · [Variant Tree](../interface/variant_tree.md)

<div class="tks-video" data-video="B2.3">How to build three finishes of one product, start to finish</div>

Make the Product, split it into Parts, fill each material pool, then save one State per finish. Every step on screen, on one product.

Read more: [Make Material Variants](../workflows/material_variants.md)

## 4. Render every finish in one go <span class="tks-min">5 <span class="tks-min__u">min</span></span> { #4-render-every-finish-in-one-go }
<div class="tks-video" data-video="B2.4">How to render every finish in one go: variants in the cascade</div>

Pick a finish on any level of the tree with the variant icon, just like a camera or a world. Then one batch render makes all of them.

## 5. A swap changed the wrong thing? Here is why <span class="tks-min">4 <span class="tks-min__u">min</span></span> { #5-a-swap-changed-the-wrong-thing-here-is-why }
<div class="tks-video" data-video="B2.5">Variant conflicts explained: collapse and shared objects</div>

Two kinds of conflict: one object wearing two materials from the same pool, or one object shared by two Products. The **Variants** warning icon shows either one before it bites.
